# Avito watcher bot — Render

Telegram-бот: следит за выдачей Авито и присылает новые объявления с подсказкой, сколько предложить.

По умолчанию объявления читает облачный Jina Reader без API-ключа. На Reader
передаются только публичные ссылки поиска и отдельных объявлений: токен Telegram,
PROXY и cookies туда не отправляются. Если Reader недоступен,
бот пробует прямую загрузку с сервера; существующий PROXY, если задан, также учитывается. По умолчанию
автопроверки запускаются раз в 5 минут. Новые обязательные переменные не нужны:
существующие ключи, `.env` и `render.yaml` сохраняются.

Каждый запрос требует свежую страницу (`X-Cache-Tolerance: 0`), проверяет статус
самого Авито внутри ответа Reader и соответствие ссылки. Страница ошибки не
считается пустым успешным поиском. Цена, название и ссылки извлекаются из Markdown
обычным кодом, без генерации текста моделью.

HTTP 301/302/303/307/308 в метаданных Reader обрабатывается как перенаправление:
готовые карточки с ценами принимаются; промежуточная или неполная страница один
раз повторно загружается браузерным движком. Страница перехода без объявлений
не считается успешным пустым поиском.

Повторный `/check` в течение пяти минут использует последний ответ для той же
ссылки, показывает давность успешных данных и время до следующего запроса.
После ошибки, включая HTTP 439, повторные команды тоже выдерживают эту паузу;
ошибка остаётся видимой. История и очередь отправки продолжают обрабатываться.
Одинаковые ссылки нескольких пользователей читаются одним запросом, при этом
фильтры и доставка применяются отдельно. После паузы нужен свежий ответ источника.

Внешний бесплатный сервис может ограничивать запросы или временно не читать Авито;
ошибка показывается в боте. Бесплатный доступ не является гарантией бесперебойной
работы. Условия и лимиты: https://jina.ai/en-US/api-dashboard/rate-limit/

`AVITO_FETCH_MODE=direct` использует загрузку напрямую/через PROXY.
В режиме `reader` прямая загрузка (с существующим PROXY, если он задан) служит резервом при ошибке Reader.

Перед отправкой нового объявления бот открывает его полную карточку, если включён
фильтр брони или заданы слова-исключения. Проверяются название и **полное описание**,
включая текст за пределами короткого фрагмента выдачи. Похожие объявления и отзывы
продавца в проверку слов не попадают. Регистр, повторные пробелы и различие «е/ё»
не влияют на совпадение; слова и фразы разделяются запятыми, пробел после запятой
необязателен. Совпадение ищется как подстрока: `сломан` также исключит `сломана`.

Забронированные скрываются по умолчанию для новых и существующих поисков. Бот
проверяет статус в карточке и явные пометки продавца: «забронировано», «в резерве»,
«бронь». «Без брони», «бронь снята» и предложение забронировать не считаются бронью.
Снятые или проданные объявления с распознанным статусом также не отправляются.

Если карточку не удалось прочитать, объявление остаётся в очереди, а не отправляется
с непроверенным описанием. Повторная проверка работает и после исчезновения объявления
из первой страницы поиска. Перед повтором отправки применяются актуальные фильтры.
За один цикл загружается до 10 новых полных карточек; остальные остаются в очереди.
Запросы Reader идут с общей паузой, ошибки карточек тоже кешируются на пять минут
(или на CHECK_INTERVAL, если он больше). `/check` показывает остаток очереди и причину
отложенной проверки. Изменение фильтров не рассылает уже просмотренные объявления заново.

Миграция SQLite при старте добавляет настройку брони, сохраняя поиски, историю
объявлений и старую очередь. Очищать базу при обновлении не нужно.

Как пользоваться:

- Чтобы добавить поиск, пришли боту ссылку с Авито, а название можно написать с новой строки (или через пробел). Без названия возьмётся текст поиска из ссылки.
- `/list` — поиски с номерами 1, 2, 3… (после удаления номера сдвигаются, дыр нет)
- `/name 1 Vita Сочи` — переименовать, `/del 1` — удалить
- `/price 1 5000 15000` — диапазон цены, `/price 1 0 0` — убрать ограничения
- `/exclude 1 чехол, на запчасти, не включается` — заменить список исключений
- `/exclude 1 -` — очистить исключения
- `/reserved 1 on` — скрывать бронь; `/reserved 1 off` — показывать бронь
- `/stats 1` — статистика цен; `/list` также показывает текущие фильтры
- `/proxy` — диагностика настроенного прокси именно с сервера бота: контрольный HTTPS-сайт,
  выдача Авито и одна полная карточка. Все запросы принудительно идут через PROXY,
  без Reader и прямого обхода; вывод не содержит адреса, логина или пароля.
  Повтор команды в течение пяти минут показывает последний результат.
- `/check` — проверка своих поисков: число прочитанных объявлений,
  отправок, исключений фильтрами и конкретные ошибки. При первом успешном чтении
  бот запоминает текущую выдачу без рассылки старых объявлений.

Токен НЕ хранится в репозитории — он задаётся в Render в переменной `BOT_TOKEN`.

Переменные:

- `SEARCHES` — поиски, по одному на строку: `ссылка | название` (на Render диск стирается при рестарте, поэтому поиски задаются здесь; /add тоже работает, но до перезапуска)
- `DEFAULT_EXCLUDE` — слова-исключения через запятую
- `CHECK_INTERVAL` — секунд между проверками
- `AVITO_FETCH_MODE` — `reader` (по умолчанию, бесплатно без ключа) или `direct`.
  Для `reader` значение CHECK_INTERVAL меньше 300 с автоматически поднимается до 300.
- `PROXY` — российский прокси для Авито, если он блокирует IP Render (`http://user:pass@host:port`)
- `PROXY_FALLBACK` — по умолчанию `1`: если соединение через прокси не установилось,
  бот пробует прямой доступ и повторяет попытку через прокси через 5 минут.
  Поставьте `0`, если запросы должны идти только через заданный прокси.
  Ошибка `CONNECT tunnel failed, response 403` означает отказ прокси на этапе
  соединения, а не отсутствие новых объявлений. HTTP 403 сам по себе не устанавливает
  причину запрета. `/proxy` отличает общий запрет HTTPS CONNECT от ограничения туннеля
  только к Авито и от ответа самого Авито (например, HTTP 429). При общем запрете
  уточните у провайдера поддержку HTTPS CONNECT и доступ с исходящих IP Render.
  HTTP 407 указывает на требование авторизации. Пароль прокси и токен бота не добавляются
  в диагностический отчёт, журналы или GitHub. Диагностика не меняет настройки и историю поисков.

Неотправленные объявления сохраняются в очереди SQLite и повторяются даже при
недоступности Авито. При недоступности фото бот отправляет текст с целой HTML-разметкой.
Пауза после блокировки Авито не мешает повторным отправкам в Telegram.

Ограничение Render Free: при остановке, перезапуске и новой публикации локальная
SQLite-база и очередь пропадают. `SEARCHES` восстанавливает ссылки, но не историю
объявлений и не настройки, введённые командами. Самопинг не даёт гарантии непрерывной
работы. Для постоянной истории нужен внешний постоянный накопитель данных либо
постоянный диск с `DB_PATH` на нём (диск недоступен на Free).
Документация: https://render.com/docs/free

Проверка исправлений без настоящих токенов и запросов к Telegram/Авито:

```bash
python -m unittest discover -s tests -v
```
